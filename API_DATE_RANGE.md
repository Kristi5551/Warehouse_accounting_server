# Контракт периода дат в API (отчёты и история операций)

Одна и та же семантика для всех query-параметров **`dateFrom`** / **`dateTo`** на сервере.

## Формат

- Строка **ISO-8601**, только календарная дата: **`yyyy-MM-dd`** (линейный формат, без локали клиента).
- Примеры: `dateFrom=2026-05-01`, `dateTo=2026-05-05`.
- Неверный формат → **400** с сообщением вроде «Неверный формат даты, ожидается YYYY-MM-DD» (`parseDateQuery`).

## Включение `dateTo`

Границы в SQL строятся через **`ReportDateBounds`**:

| Параметр | Условие в SQL |
|----------|----------------|
| `dateFrom` | `created_at >= dateFrom.atStartOfDay()` |
| `dateTo`   | `created_at < dateTo.plusDays(1).atStartOfDay()` |

Итог: **день `dateTo` входит в период целиком** (до конца суток в «локальном» смысле ниже).

**Один день:** `dateFrom=2026-05-01` и `dateTo=2026-05-01` → все операции за 1 мая.

## Только одна граница

- Только **`dateFrom`**: с указанной даты 00:00 **и дальше** (верхней границы нет).
- Только **`dateTo`**: всё **до конца** указанного дня включительно (условие только `created_at < toExclusive`).
- Оба пусты: фильтра по датам нет.

## Timezone

Для учебного / локального проекта зафиксировано:

- Используется **локальная timezone JVM сервера** (`LocalDate.atStartOfDay()` без `ZoneId`).
- В БД у `created_at` — **`TIMESTAMP WITHOUT TIME ZONE`**; сравнение в том же «настенном календаре», что и метки из приложения при локальном запуске.

Переход на **`Instant` / UTC** и явный `ZoneId` в API не делался намеренно (избегаем большой миграции).

## Эндпоинты

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/api/reports/operations` | Отчёт по операциям (`dateFrom`, `dateTo`) |
| GET | `/api/operations` | История операций (`dateFrom`, `dateTo` и др. фильтры) |
| GET | `/api/stock/products/{id}/history` | История по товару (`dateFrom`, `dateTo`) |

Реализация фильтра: **`StockRepositoryImpl.findOperations`** и **`ReportRepositoryImpl.operationsReport`** (через `ReportDateBounds`).

## Клиент Android

- В query уходят **только** строки **`yyyy-MM-dd`** или параметр **не отправляется** (пустое поле в UI).
- Валидация: `IsoCalendarDateQuery` (формат и порядок «от» ≤ «до»).
